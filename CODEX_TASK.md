# Первая задача для Codex: подготовка категории «Разработка»

## Контекст

Статический эталон страницы находится в `app/services-taxonomy-dev.html`. На действующем сайте категория редактируется через ACF, а карточки дочерних услуг выводятся автоматически.

Сейчас на одной странице смешаны типы сайтов, CMS, отдельные этапы и свойства разработки. Требуется подготовить интерфейс коммерческого хаба без полного редизайна сайта.

## Этап 1 — аудит без изменения кода

1. Изучи:
   - `app/services-taxonomy-dev.html`;
   - блок `.taxonomy` в `app/sass/main.sass`;
   - связанные правила в `app/sass/_media.sass`;
   - связанные участки `app/js/common.js`.
2. Определи повторно используемые компоненты и стили.
3. Предложи минимальный список новых секций и классов.
4. Укажи, какие существующие блоки можно сохранить без изменения.
5. Не изменяй код до подтверждения плана.

## Этап 2 — статическая вёрстка после подтверждения

После подтверждения плана:

1. Обнови только `app/services-taxonomy-dev.html`, исходные SASS и при необходимости `app/js/common.js`.
2. Сохрани существующую шапку, breadcrumbs, общий визуальный язык и автоматические карточки услуг как эталон.
3. Добавь секции:
   - основные направления;
   - что входит в разработку;
   - технологии;
   - выбранные кейсы;
   - стоимость.
4. Не добавляй вымышленные показатели и роли.
5. Используй временные нейтральные данные только там, где они явно помечены как демонстрационные.
6. Проверь адаптивность на ширинах 360, 768, 1024 и 1440 px.
7. Выполни `npm run lint:project` и `npm run build`.

## Этап 3 — WordPress

Не начинать до добавления действующей темы WordPress в репозиторий.

После её добавления:

1. Найди шаблон taxonomy категории услуг и регистрацию текущих ACF-полей.
2. Составь карту «статический блок → PHP-шаблон → ACF-поле».
3. Сохрани автоматический вывод дочерних услуг.
4. Добавь управление группой, порядком и видимостью карточек без изменения URL услуг.
5. Пустые поля и блоки не выводить.
6. Перенеси интерфейс из статического эталона в тему WordPress.
7. Проверь шаблон без заполненных новых полей: существующая страница не должна ломаться.
